Claude 对于中国大陆是最不友好的，只要有任何一点蛛丝马迹，基本上就会封锁

如果我们想使用 Claude 服务，无论是使用 Claude Design 这种客户端，还是 Claude Code（使用官方模型像是 Opus/Haiku/Sonnet）这样的 cli，其实我们核心需要搞定的问题就只有两个

## 监控原理

### 网络

Claude 对网络的监控最严格，像一般的翻墙服务还不可以，它会做这几方面的监控：

* IP 来源地：这是最直接的判断，如果来自被封禁的地区，直接拒绝服务，所以中国大陆、香港基本上都被封锁了
* 是否是机房 IP：这个特征是不会杀无赦，只是会标记成可疑，Claude 没办法判断正常用户是否也会使用机房 IP，但不正常的用户肯定会使用代理技术通过机房来访问
* IP 是否相对固定：如果一个用户的访问来源经常换，比方说今天还从日本访问过来，明天就从新加坡过来，那大概率也是有问题的，会被标记可疑

### 支付

由于海外的服务对用户的隐私的保护，除了网络这个明确的有 IP 的信息之外，就是支付方式了，通常的支付方式是信用卡：

* 信用卡号码段：这个是最容易暴露用户来源的信息，基本上也是直接拒绝服务。
* 信用卡来源：如果发现信用卡是来源是虚拟卡，也会做特别标记。容易被封
* 账单地址：这个信息也容易暴露，但如果是海外信用卡，基本上账单地址也就是海外地址了吧（或许？）

而 Claude 基本上只接收信用卡的收款方式，但有一种方式除外：**Apple Store 支付**。如果通过 Apple Store 支付，我们是可以使用礼品卡充值的，使用礼品卡充值就阻断了我们的信息暴露。

### 使用习惯

* Pro/Max: 我们有时候会发现使用 Pro 的服务的时候一切正常，当换到 Max 的时候就直接被封了，为什么？就像上面说的，Claude 除了 IP 来源和信用卡号段是直接封锁之外，其它的方式都是“疑似”，而有大量的 API 中转站是通过 Max 来服务，这就导致使用 Max 也作为一个可疑（但并不多）的标记，所以叠加上其它的程度，就可能触发封禁了。

## 应对方案

该方案笔者已经实验多次，在被封了3次之后，现在已经长期稳定使用，同时也帮朋友成功开启 Max 服务使用了半年之久

### 静态住宅 IP

* 不是说机房 IP 就一定不可行，如果是一些小众的机场，使用的人不多的时候也可以，但最稳妥的方式就是有自己的静态住宅 IP
* 静态住宅 IP 最好不要共享，就算共享也不要超过 2 个人
* 配置好你的飞机，让所有的 Claude 的流量都要走同一个 IP 出口

### 支付方式

* 现在最稳妥的支付方式就是 Apple Store 美区礼品卡

### 使用流程

如果被封禁的话不一定可以退款，可以尝试，有成功的也有失败的案例，但按照笔者说的这些方式把每一个细节都做到位基本上都能成功，笔者建议按如下的顺序逐步提升风控程度，如果有意外损失最小：

1. 注册好美区 Apple ID（免费）
2. 配置好静态住宅 IP（一般少于10美金）
3. 尝试使用 Claude 免费版一段时间，验证、预热IP，让 Claude 对这个 IP 熟悉起来
4. 购买礼品卡，开通 Pro 服务 (20美金)
5. 使用一段时间 Pro 服务，让 Claude 建立更多信任
6. 尝试开 Max 服务（100美金）
